This code is pretty simple, it basically lets us enter an arbitrary 32x32 Matrix B of GF(2) and multiplies it with the reduction in GF(2) of the matrix A from the first part. The - first lines of the resulting matrix C = AxB are then interpreted as an ARM shellcode of 6*32 bytes, which is the size of exactly 6 instructions in ARM.

Now here is the plan :

  1. Use the informations given by the first part to deduce the matrix A

  2. One you know the matrix A, write a 6 instructions ARM shellcode and calculate the matrix B to send so that the first 6 lines of the matrix C = AxB is equal to the shellcode.

Solve

Part 1 : the math

The first part is entirely related to crypto and math. The programm takes a matrix NN in GF(p) with : p = 8390077157244247764323020443580267199437209752542729239837048370032217713430994531926514756168900044622134510358316184368582052736491884552180117006536737

Note : this is a huge prime number that is constant with every execution of the programm. Also note that the matrix AA is taken from a file and is therefore constant between every execution so we have infinite tries to guess it.

The oracle returns the matrix : (A+N)q(A + N)^q with qq a 128 bits long prime number which is different at every execution.

My first thought seeing the form of this result was to use Newton’s binomial formula with NN a nilpotent matrix of order 1, which commutes with AA. This would give : (A+N)q=Aq+qAq−1N(A+N)^q = A^q + qA^{q-1}N

But this is not enough and we need more information on AA to make sure the NN we choose actually commutes with AA. However keep this idea in mind since it will be useful later.

So to have more informations on AA, I submitted a null matrix for NN to get : AqA^q.

We can’t immediately deduce AA from this because we don’t know qq and reversing a power of matrix in GF(p) with such a high power is impossible in practice.

However, I tried to think about which properties and informations on matrix remain unchanged under exponentiation. One of the most obvious to me was the diagonalizability. So I tried to diagonalize AqA^q with sage and it worked. Even though AqA^q being diagonalizable doesn’t actually mean AA is diagonalizable, I knew in many case it could be true. To be honest I don’t know enough theory to be able to proove that for this AA it was true and I probably didn’t have enough information about AA to do so anyway. But I tried several times and AqA^q was always diagonalizable so I assumed AA was probably diagonalizable for the challenge. While diagonalizing AqA^q (with a different qq each time because at every execution qq is randomly chosen as a 128bits prime) I aso noticed the diagonalized matrix always had 3 ones on the diagonal of its 3 last rows. This reinforced my thought of AA being diagonalizable and therefore having 1 as an eigenvalue with multiplicity 3.

From now we can build a plan to solve this part :

  1. Submit a null matrix for NN and get AqA^q.

  2. From the knowledge of AqA^q find DqD^q and PP such that : Aq=P−1DqPA^q = P^{-1}D^qP and DD is the diagonal matrix of AA.

  3. Choose N=E31,32N=E_{31,32} an upper triangular elementary matrix that is therefore a nilpotent matrix of order 1 that commutes with any diagonal matrix such as DD.

  4. Calculate the representation ÑÑ of NN in the diagonal basis of AA : Ñ=P−1NPÑ = P^{-1}NP

  5. Now sending this to the oracle gives us : M=(A+Ñ)q=(P−1DP+P−1NP)q=P−1(D+N)qPM =(A + Ñ)^q = (P^{-1}DP + P^{-1}NP)^q = P^{-1}(D+N)^qP

       From this deduce : S=PMP−1=(D+N)q=Dq+qDq−1NS = PMP^{-1} = (D+N)^q = D^q + qD^{q-1}N

       (I told you that Newton’s formula would come in handy at some point)

  1. The key point to notice now is that since Dq−1D^{q-1} is diagonal and N=E31,32N = E_{31,32}, the value of (D+N)q(D+N)^q at the 31th row and 32th column is equal to qq. We just found another secret value !

  2. Knowing qq we can find its inverse q−1q^{-1} in GF(p)

  3. Then calculate (Dq)q−1=D(D^q)^{q^{-1}} = D and finally reconstruct A=P−1DPA = P^{-1}DP

Part 2 : the pwn

Even though this challenge was categorized as a hard pwn challenge, to me the hard part was done with finding the matrix AA. Now the actual pwn part is much easier in my opinion.

First thing to do is to write the 6 instructions long ARM shellcode that we want to call. Obviously a shell spawning shellcode will never fit in only 6 instructions, so w’e will try to call a reading function instead to then write a longer shellcode.

The first problem is that with the call to mprotect(mem, mmap_size, PROT_READ | PROT_EXEC); just before the shellcode execution, the memory region is not writable anymore so we have to first change the memory protection. Fortunately since the function got called right before, the x8, x0 and x1 registers already contain the correct values (respectively the syscall number, the start address and the length). We just have to change the value x2 to 2 to have RWX permissions on the memory region. This takes 2 instructions (one to set x2 and one for svc). We can’t do less than that.

Now we have to setup a call to the read syscall with the 4 remaining instructions. Doing it naively would require 5 instructions :

  • 1 to set x8 to 63 (the syscall number)

  • 1 to set x0 to 0 for the stdin file descriptor

  • 1 to set x1 to the target address (using relative labels)

  • 1 to set x2 to the length to read

  • 1 to call svc.

But a quick a look at the man entry of mprotect gives us a valuable information :

RETURN VALUE
       On success, mprotect() and pkey_mprotect() return zero.  On error, these system calls return -1,  and  errno  is
       set to indicate the error.

And since the register used for storing return values is x0 after the call to mprotect x0 already contains 0. We no longer need to waste an instruction for this. Here is the final shellcode :

shellcode1 = asm('''
    mov x2, #7
    svc 0
    adr x1, toread
    mov x2, #0x100
    mov x8, #0x3F
    svc 0
toread:
''')

Now the only thing left to do is to calculate the matrix B that would result C = AxB to have its 6 first rows equal to the bits of this shellcode.

We can convert this shellcode into 6 vectors of bits (X1X_1, …, X6X_6) and building CC as a matrix with (X1,...,X6)(X_1, ..., X_6) as its 6 first rows and the rest set to 0. Then knowing AA from part 1, solve the system A×B=CA \times B=C.

This can be done very easily with sage :

F2 = GF(2)

def get_bits(n):
    b = int.from_bytes(n, byteorder='big')
    blen = b.bit_length()
    l = [0]*blen
    for i in range(blen):
        l[blen-1-i] = b & 1
        b >>= 1
    return l

target_bits = get_bits(shellcode1)

target_rows = []
for i in range(6):
    target_rows.append(target_bits[32*i:32*(i+1)])

C = Matrix(F2, 32, 32, 0)

for j in range(6):
    for i in range(32):
        C[j, i] = target_rows[j][i]

# Calc B
B = Matrix(F2, 32, 32)

for i in range(32):
    col = Ar2.solve_right(C.column(i))
    B.set_column(i, col)

assert Ar2 * B == C
